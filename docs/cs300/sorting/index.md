## 排序术语

**Sorting**: 将元素按指定规则排为升序或降序。这里默认 int 数组升序；比较一次视为常数工作。

**Stable**: 比较键相等的两个元素在排序前后的相对顺序不变。例如 `(90, Alice)` 原本在 `(90, Bob)` 前，按分数排序以后仍保持这个顺序。稳定性针对比较键，单独看相同整数无法观察它。

**In-Place**: 通常指只使用常数量额外数据存储。递归栈需单独计入；某些资料把快排的分区称为原地，但这不代表整个快排额外空间为 Θ(1)。

**Invariant**: 每轮前后都保持的性质，例如“前 i 个元素已经有序”。它能帮助解释正确性和追踪中间状态。

## 复杂度对照

下表针对这些页面明确给出的实现，N 为元素数量，K 为桶数量。最好、平均、最坏分析的都是时间；额外空间不包含输入数组。

| 算法 | 最好 | 平均或常见情况 | 最坏 | 额外空间 | 稳定性 |
|---|---|---|---|---|---|
| Selection Sort | Θ(N²) | Θ(N²) | Θ(N²) | Θ(1) | 通常不稳定 |
| Insertion Sort | Θ(N) | Θ(N²)，随机排列模型 | Θ(N²) | Θ(1) | 稳定，使用严格大于移动 |
| Bubble Sort，带提前退出 | Θ(N) | Θ(N²)，随机排列模型 | Θ(N²) | Θ(1) | 稳定，使用严格大于交换 |
| Merge Sort | Θ(N log N) | Θ(N log N) | Θ(N log N) | Θ(N)，含缓冲区与栈 | 稳定，相等先取左边 |
| Quicksort，中点值 Hoare 分区 | Θ(N log N) | 常见均衡划分为 Θ(N log N)；平均需输入模型 | Θ(N²) | 均衡 Θ(log N)，最坏 Θ(N) 的栈 | 不稳定 |
| Heapsort，迭代下沉 | Θ(N)，例如全相等且下沉提前停止 | 常见 Θ(N log N) | Θ(N log N) | Θ(1) | 不稳定 |
| Bucket Sort，桶内插入排序 | Θ(N+K)，桶内已排序等情形 | 均匀分布下期望 Θ(N+K+N²/K) | Θ(N²+K) | Θ(N+K) | 本页实现稳定 |

!!! note "实现条件决定结论"

    原资料的基础冒泡版本没有提前退出，即使已排序，也做 Θ(N²) 次比较；我们的页面同时解释基础版与提前退出版。堆排序表中最好情况针对本页下沉实现且允许重复键；不能只凭算法名称断言所有输入都耗时 Θ(N log N)。桶排序也不能不加分布和桶数条件就称为线性算法。

快排的期望 Θ(N log N) 可在随机排列等标准模型下讨论；若希望对固定输入也有期望保证，通常随机选择 pivot 或先打乱。选择中点索引不会自动得到数值中位数。

## 如何辨认算法

- 每轮寻找未排序区最小值，放到前面：Selection Sort。
- 取下一个元素，插入前面的有序区：Insertion Sort。
- 反复比较相邻元素，把最大值推到后面：Bubble Sort。
- 两半先排好，再线性合并：Merge Sort。
- 先按 pivot 分区，再分别排序：Quicksort。
- 根节点持续提供当前最大值：Heapsort。
- 先按数值区间分组，桶内排序后拼接：Bucket Sort。

## 综合自测

??? question "1. 已排序的输入，选择排序能提前变成线性时间吗？"

    这份实现不能。它仍要扫描整个未排序区以确认最小值，所以比较次数仍为 N(N−1)/2。

??? question "2. 快排分区完成以后，两边各自已经有序了吗？"

    没有。分区只保证两边满足 pivot 的大小约束，仍需递归处理内部顺序。

??? question "3. 两个排序都是 O(N²)，是否实际耗时相同？"

    不一定。O 是上界，还要看紧界、输入情况、比较和写入次数、常数与硬件。插入排序对已排序输入为 Θ(N)，选择排序仍为 Θ(N²)。
