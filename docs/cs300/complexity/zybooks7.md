根据你提供的 `7.pdf`（28 页），对应 §7.1–7.4 整理。与 [Lecture 17](../lectures/lec17-complexity.md)、[Lecture 18](../lectures/lec18-algorithmanalysis.md)、[Lecture 19](../lectures/lec19-worstcase.md) 配合阅读。这里是按知识点改写的复习讲义，Java 示例为重新编写。

## 1. 先确定分析对象

**Input Size**: 用 N 表示输入规模，例如数组长度。若还涉及字符串长度 M，就不能随意把 M 当成常数。

**Runtime**: 本章统计随规模增长的工作量，而非某台电脑上的毫秒数。先确定分析最好、最坏还是某种分布下的平均情况，再寻找它的增长阶。

**Constant-Time Operation**: 在当前模型下，耗时不随输入规模增长的操作。常数时间不等于所有操作耗时完全一样。

| 操作 | 常用模型下的成本 | 原因 |
|---|---|---|
| 固定宽度 int 的加减乘除、比较 | Θ(1) | 数值类型宽度固定 |
| 赋值一个引用 | Θ(1) | 没有复制对象内容 |
| 读写一个数组元素 | Θ(1) | 已知索引直接定位 |
| 固定执行 24 次的常数工作循环 | Θ(1) | 次数不随 N 改变 |
| 复制 N 个数组元素 | Θ(N) | 必须处理所有元素 |
| 拼接长度为 A、B 的两个一般字符串 | O(A+B) | 通常需要构造并复制结果 |

Java 的 `String b = a;` 复制引用，不复制字符；`BigInteger` 的运算不能套用固定宽度 int 的常数成本假设。调用一个方法的成本要看其实际工作，不能按“一行代码”判为 Θ(1)。

## 2. 化简增长阶

对成本函数：

$$
T(N)=7N^2+13N+5
$$

当 N 足够大时，平方项主导，常数倍不影响增长阶，因此 $T(N)=\Theta(N^2)$，也属于 $O(N^2)$。

| 成本表达式 | 紧增长阶 |
|---|---|
| 9999 | Θ(1) |
| N+9999 | Θ(N) |
| 734N | Θ(N) |
| 12N²+6N+1000 | Θ(N²) |
| N log₂N+N | Θ(N log N) |
| N³+100N² | Θ(N³) |

!!! tip "先合并实际工作，再化简"

    顺序执行的成本相加；重复调用的成本累计。不能把顺序的两个 N 次循环乘成 N²。

## 3. 四种循环，逐个数

### 顺序的循环：相加

```java
for (int i = 0; i < n; i++) {
    total += a[i];
}
for (int i = 0; i < n; i++) {
    total -= b[i];
}
```

假设 a、b 至少有 n 个元素，算术为常数工作。总共处理 2n 个元素，时间 Θ(N)。

### 两个独立规模：保留变量

外层 N 次、每次内层 M 次，时间 Θ(NM)。只有当 M=N，才写成 Θ(N²)。

### 三角形循环：求和

```java
for (int i = 0; i < n - 1; i++) {
    for (int j = i + 1; j < n; j++) {
        compare(a[i], a[j]); // 假设一次 compare 为 Θ(1)
    }
}
```

比较次数为：

$$
(N-1)+(N-2)+\cdots+1=\frac{N(N-1)}2
$$

所以总时间 Θ(N²)。内层次数在减少，并不意味着总时间是线性的。选择排序正是这样的累计方式。

### 每次减半：数层数

```java
int steps = 0;
for (int remaining = n; remaining > 0; remaining /= 2) {
    steps++;
}
```

对 n≥1，循环执行 $\lfloor\log_2 n\rfloor+1$ 次，时间 Θ(log N)。若循环中还扫描 N 个元素，则总时间变成 Θ(N log N)。

## 4. 最好、最坏与平均情况

以遇到目标立即返回的线性查找为例：

| 情况 | 输入示例 | 时间 |
|---|---|---|
| Best Case | 第一个元素即目标 | Θ(1) |
| Worst Case | 最后才找到或不存在 | Θ(N) |
| Average Case | 需要先说明目标出现位置的概率等假设 | 在常见均匀位置模型下为 Θ(N) |

平均时间不能直接取最好与最坏时间的算术平均。最坏情况分析也不能选择不可能同时发生的分支条件，得到一个不存在的“最坏输入”。

## 5. O、Ω、Θ：先选成本函数，再说界

**Big-O**: 渐近上界。存在常数 c>0 和 N₀，使 N≥N₀ 时 $T(N)\le c g(N)$。

**Big-Omega**: 渐近下界。存在常数 c>0 和 N₀，使 N≥N₀ 时 $T(N)\ge c g(N)$。

**Big-Theta**: 同时有同阶上界、下界，描述紧增长阶。

例如 $T(N)=2N^2+N+9$。对 N≥1：

$$
2N^2\le T(N)\le12N^2
$$

所以 $T(N)=\Theta(N^2)$。它也有更宽松的 O(N³) 上界，但不能因此称它为立方阶。

资料 §7.4 也会讨论同时包住最好与最坏成本的界；正式使用渐近记号时，最好明确你研究的是哪一个函数。O 不是“最坏”的同义词，Ω 也不是“最好”的同义词。

## 6. 增长阶速查

| 增长阶 | English Term | 典型例子 | N 翻倍的主导成本变化 |
|---|---|---|---|
| Θ(1) | Constant | 按索引取值 | 不变 |
| Θ(log N) | Logarithmic | 最坏二分查找 | 约增加常数量 |
| Θ(N) | Linear | 扫描数组 | 约 2 倍 |
| Θ(N log N) | Linearithmic | 归并排序 | 略大于 2 倍 |
| Θ(N²) | Quadratic | 选择排序比较次数 | 约 4 倍 |
| Θ(N³) | Cubic | 三层各执行 N 次的循环 | 约 8 倍 |
| Θ(2ᴺ) | Exponential | 输出所有 N 位二进制选择的叶节点数量 | 原来的约 2ᴺ 倍 |
| Θ(N!) | Factorial | N 个不同元素的全排列数量 | 增长极快 |

这里的翻倍比例描述主导项，不是每次运行的精确比值。输出长度和每次比较的成本仍须另外计算。

## 自测

??? question "1. 两层循环一定是 O(N²) 吗？"

    不一定。外层固定 24 次、内层 N 次是 Θ(N)；外层 N 次、内层每次 log N 次是 Θ(N log N)。应累计实际执行次数。

??? question "2. N 从 100 增至 1000，平方阶主导成本约变多少？"

    规模变成 10 倍，平方主导项约变成 100 倍。

??? question "3. 二分查找的 Θ(log N) 是否包含先排序的成本？"

    不包含。数组已经按同一比较规则有序，才可直接二分。若需先排序，单次查询的整体成本还要加上排序。
