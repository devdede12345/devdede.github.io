## 本讲主线

明确最坏与最好输入，识别反复减半或翻倍的循环，再区分渐近上界、下界和紧界。

## 为什么减半对应 log N

```java
static int countDoublings(int n) {
    int steps = 0;
    for (long value = 1; value < n; value *= 2) {
        steps++;
    }
    return steps;
}
```

对于正整数 N，循环经历约 $\lceil\log_2 N\rceil$ 次。这里用 long 避免 int 翻倍产生溢出后破坏循环条件。

典型对数增长在规模翻倍时只增加约一个主要步骤；不是步骤数也翻倍。

## 线性搜索的不同输入

假设数组有 N 个元素，逐个比较，找到就立即返回：

| 输入情况 | 主要比较次数 |
|---|---|
| 第一个元素就是目标 | 1 |
| 目标在最后 | N |
| 根本没有目标 | N |

**Best Case**: 在固定规模下，选择让算法工作量最小的输入。

**Worst Case**: 在固定规模下，选择让算法工作量最大的输入。

平均情况（Average Case）还需要输入分布，不能只取最好和最坏的算术平均。

## O、Ω、Θ 的严谨含义

| 记号 | 意义 |
|---|---|
| $O(g(N))$ | 渐近上界（Upper Bound） |
| $\Omega(g(N))$ | 渐近下界（Lower Bound） |
| $\Theta(g(N))$ | 同阶的渐近上下界，即紧界（Tight Bound） |

课件第 15–16 页把 O 与最坏情况、Ω 与最好情况对应，并用 “no Θ” 表达两种情况不同。这是该处课堂对比的简写。**正式定义里，O 不等于“最坏情况”，Ω 也不等于“最好情况”；必须先说明分析哪个成本函数。**

| 算法 | 最好情况的紧界 | 最坏情况的紧界 |
|---|---|---|
| 线性搜索 | $\Theta(1)$ | $\Theta(N)$ |
| 二分搜索 | $\Theta(1)$ | $\Theta(\log N)$ |
| 扫描所有元素求最大值 | $\Theta(N)$ | $\Theta(N)$ |
| 两两比较、遇到重复立即返回 | $\Theta(1)$ | $\Theta(N^2)$ |

因此，不能笼统说“二分搜索没有 Θ”；它的最坏情况本身具有 $\Theta(\log N)$ 的紧界。

## 分析前确认假设

二分搜索要求排序；使用快速索引结构才能支持这里的操作模型。若比较字符串，并让标题长度也增长，应把比较成本一起计算。

课件将固定长度级别的标题比较当作常数开销，是针对歌曲数量 N 的建模假设，不是说任意 `.equals()` 永远都是 $O(1)$。

??? success "自测：只证明一个算法属于 O(N²)，能否断言它不是 O(N)？"

    不能。线性成本也满足平方上界。要确定紧增长阶，需要更精确的上下界。
