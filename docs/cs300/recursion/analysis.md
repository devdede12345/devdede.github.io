## 1. 递推关系怎么写

**Recurrence Relation**: 用较小输入的成本表示当前输入的成本。先数实际递归调用，再加上本层除递归以外的工作。

$$
T(N)=\text{本层工作}+\sum\text{实际执行的子调用成本}
$$

下面默认基本情况成本为 Θ(1)，并省略取整以突出增长阶。

| 递推关系 | 紧时间界 | 思路 |
|---|---|---|
| T(N)=T(N−1)+Θ(1) | Θ(N) | N 层，各常数工作 |
| T(N)=T(N−1)+Θ(N) | Θ(N²) | N+(N−1)+…+1 |
| T(N)=T(N/2)+Θ(1) | Θ(log N) | 只有一条减半路径 |
| T(N)=2T(N/2)+Θ(1) | Θ(N) | 二叉树总节点数为线性 |
| T(N)=2T(N/2)+Θ(N) | Θ(N log N) | 每层合计 N，约 log N 层 |

最后两行说明：两个递归调用并不一定是指数时间，子问题缩小速度同样重要。反之，两次规模仅减一的调用 `2T(N−1)+Θ(1)` 则为 Θ(2ᴺ)。

## 2. 递归树：每层总工作量

**Recursion Tree**: 节点标记当前调用自身的工作，边表示子调用。不能把已经含子调用的 T(N) 再和所有子节点成本重复相加。

归并排序的结构：

| 深度 | 调用数量 | 每个调用的本地工作 | 该层合计 |
|---|---|---|---|
| 0 | 1 | N | N |
| 1 | 2 | N/2 | N |
| 2 | 4 | N/4 | N |
| d | 2ᵈ | N/2ᵈ | N |

到规模 1 需要约 log₂N 层，所有层累计 Θ(N log N)。如果每个节点只是常数工作，就应数整棵树的节点数，而不是机械使用“每层 N”。

## 3. 线性查找与二分查找

**Linear Search**: 一个一个检查，允许输入无序。最好 Θ(1)，最坏 Θ(N)。

**Binary Search**: 在已按同一规则排序的随机访问序列上，比较中点，只进入可能包含目标的那一半。最好 Θ(1)，最坏 Θ(log N)。

二分查找会丢弃另一半，因此每层只递归一次，不是两次。

```java
static int binarySearch(int[] a, int key, int low, int high) {
    if (low > high) {
        return -1;
    }
    int mid = low + (high - low) / 2;
    if (a[mid] == key) {
        return mid;
    }
    if (key < a[mid]) {
        return binarySearch(a, key, low, mid - 1);
    }
    return binarySearch(a, key, mid + 1, high);
}
```

a 非 null 且升序，初始调用 `binarySearch(a, key, 0, a.length - 1)`。这里使用包含两端的区间 `[low, high]`，命中失败的基本情况是 low>high；low==high 时还有一个元素，必须检查。

资料部分例子保留中点在某个子区间，并用“只剩一个元素”判断失败；这里用的是排除已比较中点的版本。两种边界写法不要混用。

### 手工追踪

在 `[3, 7, 11, 18, 25, 32, 46]` 中查找 25：

| low | high | mid | a[mid] | 下一步 |
|---|---|---|---|---|
| 0 | 6 | 3 | 18 | 查右半边 [4,6] |
| 4 | 6 | 5 | 32 | 查左半边 [4,4] |
| 4 | 4 | 4 | 25 | 返回 4 |

mid 用 `low + (high-low)/2`，避免直接相加两个大索引造成溢出。重复值存在时，上述方法返回某个匹配位置，不保证第一个。

## 4. 时间与空间分别数

这个二分版本每层 Θ(1)，最坏有 Θ(log N) 层，因此时间和额外调用栈都是 Θ(log N)。改用循环维持 low、high 后，最坏时间相同，额外空间为 Θ(1)。

归并排序虽然栈深也为 Θ(log N)，但还要算辅助数组，通常额外空间 Θ(N)。全排列深度为 N，却有 N! 个叶节点。不要把深度、总调用数、结果数量混为一谈。

!!! tip "索引缩小区间，避免复制"

    二分查找应传索引。如果每次复制半个数组，成本变成 T(N)=T(N/2)+Θ(N)，总复制量 N+N/2+…=Θ(N)，不再是 Θ(log N) 时间。

## 自测

??? question "1. T(N)=2T(N/2)+Θ(1)，为什么不是 Θ(log N)？"

    log N 是深度。第 d 层有 2ᵈ 个调用；各层节点总数约为 1+2+4+…+N=Θ(N)。

??? question "2. 二分查找必须先排序吗？"

    必须已有与比较规则一致的排序；排序可以由此前的操作完成。如果只是查询一次，先排序再二分未必比直接线性扫描划算。

??? question "3. 查找失败的最后一个空区间调用要算吗？"

    要。问精确调用次数时要说明是否包含初次调用、失败基本情况调用；这些常数差别不改变 Θ(log N) 的最坏增长阶。
